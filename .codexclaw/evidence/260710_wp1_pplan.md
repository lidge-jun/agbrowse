# WP1 P Plan - Authenticated ChatGPT Work Reprobe

Date: 2026-07-10
Class: C3 user-facing browser contract
Loop archetype: spec-satisfaction

## Loop spec

- Trigger: GPT-5.6 Chat/Work UI changed and Work automation needs exact live DOM evidence.
- Goal: capture the 5 checks in `01_ui_contract_evidence.md` section 5.1 and the 10 checks
  in `04_work_surface_support.md` section 7.2, including one Work submit-to-complete trace.
- Non-goals: no Chat prompt, account/settings mutation, cookie/storage inspection, project or
  attachment automation, public-web research, source implementation, or repeated paid tasks.
- Verifier: authenticated browser DOM snapshots/readbacks after each transition plus Computer Use
  where the in-app browser cannot operate a control, one screenshot at the stable Work surface and
  task states, and the 15-row ledger below with rooted locators, exact attributes/text/count/URL,
  artifact reference, restoration, and status. See the execution-method amendment below.
- Stop condition: all 15 rows are resolved as PASS under the row-specific requirement. Any
  UNOBSERVED or CONTRADICTORY row keeps WP4 closed. A naturally absent conditional state is
  recorded inside its row and cannot justify a selector-specific implementation claim.
- Memory artifact: updates to `01_ui_contract_evidence.md`,
  `04_work_surface_support.md`, and a WP1 browser evidence receipt.
- Expected outcome: DONE. BLOCKED only for repeated authentication/external-state failure;
  NEEDS_HUMAN only if live UX contradicts the fixed required-power CLI/MCP contract.
- Escalation: do not infer hidden DOM or expand v1 inputs when a control cannot be observed.

## Resource bounds

- Tool/credential scope: start with the existing signed-in IAB session. After explicit user
  steering, the same-account authenticated Chrome profile may be used through Computer Use plus
  Chrome DOM readback when IAB control is unavailable. The unauthenticated agbrowse profile is
  observation-only and receives no Work mutation.
- Browser mutations: Chat/Work toggle, picker controls, Power 1..6, Advanced selectors,
  Speed Standard/Fast, and one benign Work prompt.
- Write scope: `devlog/_plan/260710_gpt56_update/01_ui_contract_evidence.md`,
  `04_work_surface_support.md`, `.codexclaw/evidence/`, and goalplan state.
- Prompt budget: one Work task at Power 1 + Standard, no attachments/projects, no Chat send.
- Wall clock: 45 minutes for this probe cycle.

## Dependency-ordered procedure

1. Start with `globalThis.iab` and read its complete documentation before interaction. If IAB
   control becomes unavailable, stop IAB mutation. A switch to another authenticated profile is
   allowed only after explicit user steering and a recorded method amendment.
2. Verify authenticated ChatGPT UI before any product mutation. The executed amendment used the
   user's authenticated Chrome profile through Computer Use, with Chrome DOM readback after each
   transition. The separate agbrowse profile redirected to sign-in and was not mutated.
3. Capture initial Chat/Work, Power, Model, Effort, and Speed settings. Enter Work under the
   activation matrix and record composer ownership, Power ARIA, and simple/advanced roots.
4. Round-trip Power 1..6, then Model/Effort/Speed and Chat/Work state persistence without submit.
   Restore and verify the captured initial settings.
5. Set Power 1 + Standard explicitly. Submit exactly:
   `Return exactly WORK_PROBE_260710_<nonce>. Do not browse, use apps, tools, files, repos,
   projects, attachments, approvals, or external actions.`
6. Capture commit/running/complete, URL/task identity, reload/re-entry, Copy/Share/Stop, and any
   naturally occurring blocked/approval/error state. Never induce negative or approval states.
7. Restore and verify the initial settings. R07 is mandatory: create a disposable verification
   tab in the authenticated profile, load the completed task, close only that agent-created tab,
   create another verification tab, navigate to the exact captured task URL, and verify completed
   task identity/result restoration. Do not generalize this to running-task resume.

Activation proof is the observed state transition plus DOM readback after every click; a click
without checked/ARIA/pill/URL evidence does not satisfy a row.

## Surface activation matrix

| Pre-state | Allowed action | Required readback |
| --- | --- | --- |
| exact Chat active | click the one exact Work radio once | exact Work active, Chat inactive |
| exact Work active | zero toggle clicks | Work remains exact active |

Every row records: precondition, bounded action, rooted locator, exact attributes/text/count/URL,
artifact, restoration, and `PASS|UNOBSERVED|CONTRADICTORY`. PASS means the row's stated bounded
claim is proven, not that untriggered negative states were invented.

| --- | --- | --- |

Any missing core action/readback is UNOBSERVED and blocks WP4. CONDITIONAL DOM absent from W04/R04
or the explicitly excluded project/attachment mutation in R10 never becomes an implementation
selector; it remains generic/fail-closed until a separately authorized probe exists.

## Execution-method amendment (2026-07-10, before submit)

The audited initial plan was IAB-only. During execution, IAB could inspect Work but could not
reliably operate the Power slider and later timed out attaching to the webview. The user then
explicitly directed: use agbrowse CDP and Computer Use, confirmed the relevant logged-in browser,
and granted the bounded policy scope. `agbrowse doctor`/headed CDP succeeded, but its separate
profile was unauthenticated and redirected to Google sign-in. It was used only to prove that
profile split and for public-source fetches.

The single safe Work submit and UI mutations therefore moved to the user's authenticated Chrome
profile through Computer Use; Chrome DOM snapshots provided readback. The safety envelope did not
expand: one Power-1/Standard prompt, no project/attachment/plugin/app/browser action, no credential
or storage inspection, and only agent-created verification tabs closed. The user's original tab
was retained and restored to Work Power 2/Standard.

This amendment supersedes only the browser-control method and R07 tab-lifecycle wording. The
15 bounded claims, one-submit budget, no-negative-state rule, restoration requirement, and v1
scope remain unchanged. A fresh C-gate audit must pass this amended envelope before WP1 closes.
